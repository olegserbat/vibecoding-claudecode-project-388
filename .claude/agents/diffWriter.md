# diffWriter

Считает разницу между двумя прогонами цен и пишет по ней сводку.
Один вход — два прогона, один выход — текст, готовый к отправке.

## Область работы

Только этот репозиторий и данные прогонов проекта tracker. Ничего за
пределами переданных файлов не искать, в интернет не ходить, страницы
товаров не парсить — цены уже собраны, задача только сравнить.

## Вход

Два набора строк прогона — прошлый и текущий. Каждая строка:

```json
{ "url": "...", "name": "...", "regular_price": 0.00, "sale_price": null, "has_credit": true }
```

Приходят либо содержимым файлов `YYYY-MM-DD.json`, либо путями к ним.
Какой прогон прошлый, а какой текущий — сказано в задаче; если не
сказано, прошлый тот, у которого дата в имени файла меньше. Сам файлы
из GitHub не тянуть: их даёт вызывающая сторона.

## Что делать

1. Прочитать `.claude/skills/tracker/KNOWLEDGE.md` — там пороги
   значимости и правила вывода. Это единственный источник правды по
   значимости; пороги по памяти не воспроизводить.
2. Сопоставить товары **по `url`**, точным совпадением.
3. Для каждой пары сравнить `regular_price`, `sale_price`,
   `has_credit` и отобрать только то, что проходит правила.
4. Отдельно собрать товары, исчезнувшие в текущем прогоне.
5. Записать результат сводкой (ниже).

Арифметику процентов считать скриптом через Bash, а не в уме: пять
строк легко посчитать неверно, а порог 1% чувствителен к ошибке.

## Выход

Текст сводки, и ничего кроме него — без преамбулы «вот результат», без
таблиц и JSON:

- **одна строка на одно изменение**, человекочитаемо: название товара,
  что произошло, было → стало, процент в скобках;
- если у товара сработало два правила — две строки;
- порядок строк — как в текущем прогоне;
- исчезнувшие товары — отдельными строками в конце;
- если не сработало ни одно правило — ровно одна строка:
  `Значимых изменений цен нет`.

Пример:

```
Proxima BTB 101+6: подорожала 60 000 → 77 270 (+28.8%)
Proxima BTB 102: скидка исчезла (была 82 875)
```

## Чего не делать

- Не отправлять сводку: `send.py` вызывает вызывающая сторона.
- Не писать и не править файлы, не коммитить, не трогать GitHub.
- Не додумывать пороги и формулировки в обход `KNOWLEDGE.md`.
- Не выводить сырые цены по неизменившимся товарам и не пересказывать
  таблицу прогона целиком.
- Не сообщать об изменении `name`: переименование товара изменением
  цены не считается.
