# Куда класть секретные токены

Коротко: **секреты не хранятся в файлах репозитория**. Для них есть три места —
по одному на каждый сценарий.

## 1. Локальная работа на своей машине → файл `.env` в корне проекта

```bash
cp .env.example .env
# открыть .env и вписать реальные значения
```

`.env` уже занесён в `.gitignore`, поэтому в `git status` он не появляется и
уехать в публичный репозиторий не может. В git коммитится только `.env.example`
— шаблон с именами переменных и заглушками вместо значений.

Проверить, что файл действительно игнорируется:

```bash
git check-ignore -v .env    # должна вывестись строка правила из .gitignore
git status --short          # .env в списке быть не должен
```

Подключить переменные в текущую сессию терминала:

```bash
set -a && . ./.env && set +a
```

## 2. Совсем не в проекте → домашняя директория

Если токен нужен нескольким проектам или не хочется держать его рядом с кодом,
он кладётся вне репозитория — тогда его физически нечем закоммитить:

```bash
mkdir -p ~/.config/secrets && chmod 700 ~/.config/secrets
printf 'export GITHUB_TOKEN=...\n' > ~/.config/secrets/env
chmod 600 ~/.config/secrets/env
```

и подгружается из `~/.bashrc` / `~/.zshrc`:

```bash
[ -f ~/.config/secrets/env ] && . ~/.config/secrets/env
```

Для Claude Code переменные окружения задаются в `~/.claude/settings.json`
(секция `env`) — это тоже вне репозитория. Файл `.claude/settings.local.json`
внутри проекта тоже подходит и уже добавлен в `.gitignore`, но домашний
`~/.claude/settings.json` надёжнее.

## 3. GitHub Actions → Secrets репозитория

Для workflow значения хранятся на стороне GitHub, а не в файлах:
`Settings → Secrets and variables → Actions → New repository secret`.
В workflow они подставляются как `${{ secrets.ИМЯ }}` — ровно так, как в
`.github/workflows/hexlet-check.yml` уже сделано с `HEXLET_ID`.

## Чего делать нельзя

- Писать реальный токен в `.env.example`, `README.md`, в файлы скилов
  (`.claude/skills/**`) или в текст задачи — всё это коммитится.
- Класть секрет в любой файл внутри репозитория, не покрытый `.gitignore`.
- «Спрятать» токен, добавив файл в `.gitignore` уже **после** коммита —
  `.gitignore` не действует на файлы, попавшие под контроль версий.
  Такой токен считается скомпрометированным: его нужно отозвать и выпустить
  заново, а файл убрать из индекса (`git rm --cached <файл>`).
